# M36 모바일 UI 마이그레이션 (4.37MB WML)

**대상 게임 빌드:** Wayward_WML_ko.html / 2026-11-01 (pre7 mapping and UI component aliases retained)
**기준 HTML:** 4,373,978 bytes (4.37MB)
**모드 버전:** 1.3.15

이 모드는 4.37MB WML 빌드 전용 모바일 UI 모드입니다. 원본 게임의 React 상태·위치 컴포넌트를 새로 그리지 않고, 원본 요소를 그대로 행동 선택지 위 고정 영역으로 옮깁니다.

## 적용 기능

- **원본 위치·인물 목록 이동:** 이야기 탭 안의 원본 위치·인물 목록(loe)을 통째로 재사용해 행동 선택지 위에 고정합니다. 이 목록의 현재 위치, 당신의 행동 상태, 인물별 기력·기분·신뢰·이목을 끄는 정도·흥분도(원본 표시 조건 충족 시), 관계 문구를 별도 계산으로 복제하지 않습니다. 흥분도 막대는 원본과 동일하게 수치가 5를 초과할 때만 표시됩니다. 상단 초상화 카드(Z0)는 원래 위치에 그대로 둡니다.
- **이야기 탭 나레이션 전용화:** 이야기 탭의 위치·인물 요약, “당신의 대응이 필요한 상황” 목록, 영업 준비 UI를 제거하고 원본 나레이션 컴포넌트(Zot)만 남깁니다. 2026-11-01 빌드의 실제 알림 컴포넌트 이름은 Voe이며, 같은 목록이 가게 상태 패널에 나타나는 경우에는 제거하지 않습니다.
- **전체화면 버튼:** 상단 삼선 메뉴 바로 왼쪽에 추가합니다. 전체화면 진입 의도를 저장합니다. 앱 전환·화면 복귀 이벤트에서는 상태만 갱신하고, 복귀 후 첫 실제 터치가 끝나는 시점(pointerup/touchend)에 전체화면 요청을 실행합니다. 전체화면 해제 의도는 이 버튼을 눌렀을 때만 저장합니다.
- **대화·게이지 고정:** 행동 이벤트의 원본 제목, 인물/행동 설명, 질문 문구, `당신 / 그녀` 게이지(원본 이벤트에서 제공될 때), 대화 상자를 선택지 위 고정 영역에 함께 배치합니다. 질문의 응답 버튼과 일반 선택지는 별도 스크롤 영역에 남기며, 원본 이벤트 콜백과 선택지 ID를 그대로 유지합니다.
- **세 번째 탭 고객 대화 이동:** 원본 손님 대화 렌더러(cst)가 만든 제목·설명·대화 문구는 기존 인물·위치 고정 패널 바로 아래에 한 번만 표시합니다. 원본 세 번째 탭에서는 대화 제목·설명·나레이션과 선택지 버튼 그리드를 모두 제외합니다. 선택지 그리드는 행동 선택지 일반 스크롤 맨 위에 한 번만 표시하며, 고정 영역에는 선택지를 넣지 않습니다. 원본 React 요소를 그대로 이동하므로 dispatch 콜백과 선택지 ID는 변경하지 않습니다. 두 포털 대상이 모두 준비되지 않은 경우에는 원본 카드 전체를 그대로 표시해 선택지를 잃거나 부분 중복시키지 않습니다. 스크롤 대상이 늦게 생성되거나 없을 때도 원본 탭의 선택지는 보존됩니다.
- **고객 헤더 2행:** 첫째 줄에는 고객 이름과 원본 골드·인내심 표시를 유지하고, 둘째 줄에는 진행 상태·주문·응대 설명을 모아 표시합니다. 긴 문구는 말줄임표로 줄이고 전체 설명은 제목(툴팁)에 남깁니다. 원본 클릭·응대 버튼·인내심 계산은 그대로 유지합니다.
- **영업 준비·시설 업그레이드 이동:** 기존 wst 컴포넌트에서 대출 상환, 물자 채우기, 공급 목표·가격 제한·구매 제외 설정, 시설 업그레이드 아코디언만 골라 선택지 패널의 원본 행동 스크롤 앞에 배치합니다. 게임 컴포넌트를 새로 계산하거나 버튼을 재구현하지 않고 원본 React 요소를 한 번만 이동하므로 `stock_up`의 `skip` 값, `pay_debt`, `set_supply_target`, `set_supply_price_limit`, `buy_quality_upgrade` 콜백과 상태 훅은 그대로 유지됩니다. 영업 준비의 대기·목욕·팁 설정은 이동 대상에서 제외합니다. 기존 반응형 트리에서 같은 이야기 본문이 데스크톱 숨김 영역과 모바일 탭에 중복 참조되더라도 wst는 한 번만 렌더링합니다.
- **선택지 하단 이동 버튼:** 좌우 행동 패널 이동 버튼을 스크롤 영역 밖의 고정 footer로 분리하고 높이를 1.5rem로 고정합니다. 66.666% 스크롤 제한은 세로 모바일에만 적용하고 가로·데스크톱에서는 원본 높이를 유지합니다.
- **선택지 영역 축소:** 행동/대화 선택지의 스크롤 영역을 부모 영역의 약 2/3 높이로 제한해 위쪽 상태·대화 고정 영역과 화면 공간을 나눕니다.
- **비활성 행동 축약·접기:** 사용 불가 선택지를 짧은 이름과 사유로 축약합니다. ‘일하기’, ‘외출’, ‘마을 둘러보기’ 분류에 비활성 선택지가 있으면 기본으로 접고, 분류 제목을 눌러 펼치거나 다시 접을 수 있습니다.

2026-11-01 빌드에서는 위치 목록·게이지·대기 질문 컴포넌트의 minified 이름(qoe/wb/snt)을 이전 빌드 이름(loe/fb/utt)으로 정규화해 탐색합니다. 두 빌드의 해당 React 함수는 JSX 태그·props·CSS 클래스 구조까지 대조했습니다.

상태 패널 이동은 세로 모바일 화면에만 적용합니다. 가로 화면과 데스크톱에서는 원본 상태·이야기 구성 그대로 유지하며, 추가 고정 패널과 전체화면 버튼은 숨깁니다.


- **모바일 판별 보강:** WML host 라벨과 User-Agent가 모바일을 표시하지 않는 WebView에서도 실제 CSS 뷰포트 폭(1023px 이하)을 확인해 모바일 레이아웃 훅이 빠지지 않도록 보완합니다. 실행 중 상태 조회에는 영업 준비 패널이 선택지 스크롤 안으로 들어갔는지 여부를 별도로 표시합니다.

## 설치

1. 압축 파일 안의 mobile-ui-migration 폴더를 게임의 기존 wml/mods 폴더에 복사합니다.
2. 기존 wml/mods/mods.js의 WML.enable([...]) 목록에 다음 모드 ID를 추가합니다.

       "mobile-ui-migration",

   기존 활성 모드 항목을 지우거나 목록 전체를 교체하지 말고, 기존 목록에 항목 하나만 추가하세요.
3. 게임을 새로고침합니다. WML 모드 관리자에서 **M36 모바일 UI 마이그레이션 1.3.15**이 로드되었는지 확인합니다.

WML 모드 폴더 가져오기를 지원하는 실행기에서는 압축을 푼 mobile-ui-migration 폴더를 모드 관리자로 가져와도 됩니다.

## 안전 범위

이 모드는 다음 게임 동작이나 데이터를 변경하지 않습니다.

- 게임 턴, 행동 선택 및 이벤트 해결
- 경제, 물자, 공급, 캐릭터 행동 및 RNG
- 세이브/로드 데이터와 게임 ID
- Undo 처리와 원본 게임 상태

WML 훅에서 기존 React 위치·인물 목록과 wst 영업 준비 요소의 표시 위치만 이동합니다. 영업 준비 요소 중 필요한 원본 자식만 보존해 선택지 패널에 표시하며, 각 이벤트 핸들러와 상태 계산은 기존 게임 컴포넌트를 그대로 사용합니다. 비활성 버튼은 교체하지 않고 표시용 속성과 접힘 상태만 적용합니다.
