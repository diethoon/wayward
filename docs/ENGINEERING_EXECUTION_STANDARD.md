# 공통 개발 실행·검증·검수 표준

이 표준은 이 저장소의 모든 분야와 작업 브랜치에 적용한다. 프로젝트별 구현 요구사항을 대체하지 않으며 사용자의 최신 지시와 승인 범위를 우선한다.

## 역할
**구현 담당자**
- 지시 범위만 최소 수정하고, 구문·정적 분석·컴파일 오류를 확인·수정한다.
- 변경 코드의 직접 연결(호출·이벤트·데이터 흐름)을 확인한다.
- 구현에 필수적인 최소 단위 테스트와 필수 빌드만 수행한다.
- 보안·데이터 손실·마이그레이션·기존 기능 손상 위험은 직접 검증한다.
- 수정 파일, 커밋 SHA, 빌드·테스트 결과, 미해결 사항만 간결히 보고한다.
- 전체 레포 회귀, 전체 UX 재검수, 변경 무관 기능 재검증, 최종 통합 검수를 중복 수행하지 않는다.

**분야별 총괄 참모 / 최종 검수 담당자**
- 지시가 요구사항·승인 범위에 맞는지 관리하고 실제 diff·커밋·검증 증거를 대조한다.
- 통합 영향, 회귀, 분야 간 계약·호환성 및 UX를 검수한다.
- 구현 단계 검증을 이유 없이 반복하지 않고 기존 증거를 재사용한다. 위험·증거 부족 항목만 표적 재검증한다.
- 결함은 재현 조건·근거·수정 범위를 특정해 전달한다.
- 사용자 승인 없이 main 병합, 릴리스, 배포하지 않는다.

## 검증 및 중복 방지
1. 구현: 변경분 구문/컴파일, 직접 연결, 필수 최소 테스트·빌드.
2. 통합 검수: 총괄이 diff와 계약을 확인하고 영향에 비례해 통합·회귀 검증을 선택.
3. 전체 CI/회귀 검증은 통합 검수 담당자가 판단한다. 동일 커밋·동일 환경의 유효한 성공 결과는 불필요하게 재실행하지 않는다.
4. 변경 무관 영역을 포함하는 CI는 영향과 기존 결과를 확인해 필요한 작업만 수행한다.
5. 생략한 검증의 이유와 미검증 범위를 밝힌다. 실행하지 않은 테스트를 통과했다고 보고하지 않는다.
6. 필수 검증 실패는 원인을 수정해 필요한 범위에서 재실행한다. 테스트 삭제·비활성화·축소로 성공을 가장하지 않는다.

## 범위와 보존
- 승인된 요구사항만 최소 변경한다. 검증 완료 기능, 무관 모듈, 다른 분야의 저장소·브랜치는 임의 수정하지 않는다.
- 승인 없는 리팩터링, 의존성 교체, 전체 포맷 변경, 파일 이동, 추가 기능을 금지한다.
- 기존 데이터·설정·자산·인증 정보·페어링·저장 형식의 호환성과 보존을 우선한다.
- 보안·개인정보·권한·네트워크·저장소 변경은 실제 동작과 실패 경로를 직접 확인한다.
- 독립 진행 가능한 작업은 멈추지 않는다. 사용자 결정이 필요한 충돌·파괴적 변경만 구체적으로 질문한다.

## 브랜치·보고
- 시작 시 저장소, 브랜치, 기준 커밋, 작업 범위를 확인한다.
- 지정 브랜치에서만 작업한다. 기존 작업물 덮어쓰기와 force push를 금지하고 충돌 시 보존한다.
- 커밋 목적을 명확히 하고 SHA와 수정 파일을 보고한다.
- 병합·릴리스·배포는 별도 승인 없이 하지 않는다.
- 구현 보고: 저장소/브랜치/기준 커밋, 변경 파일·핵심 변경, SHA, 수행한 필수 검증, 미수행 검증과 이유, 남은 위험.
- 총괄 보고: 요구사항별 판정, diff 근거, 표적 재검증, 미해결 결함, 승인 여부.

**최우선:** 속도는 불필요한 중복 제거로 확보한다. 필수 검증·보안 확인·데이터 보존은 생략하지 않는다. 구현자와 최종 검수자의 책임을 분리하고 각 단계는 필요한 증거만 생산한다.
