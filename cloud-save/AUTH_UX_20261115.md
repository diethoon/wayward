## Adapter decision and flow

| Environment | Adapter | Expected behavior |
|---|---|---|
| Android/native launcher exposing the `WMLHost` marker | `android-native` fixed at setup even if auth methods are absent | native-only dispatch; missing API fails closed; forced account selection requires `startGoogleDriveAuthWithPolicy`; nonce-scoped result retrieval; no GIS fallback |
| HTTPS / allowed localhost | `browser-gis` fixed at setup | GIS `requestAccessToken` called synchronously from game-button click; no auth-061 popup |
| PC `file://` | `file-token-bridge` fixed at setup | opener-based static HTTPS bridge, nonce/source/Origin checks; real endpoint availability remains unverified |

`forceSelectAccount` never chooses or changes the transport. First connection and explicit logout set it to `true`; if the native policy API is missing, CloudSave returns an explicit unsupported error instead of silently using the legacy method or browser GIS.

## Android first-login / relogin

- Read-only inspected Android launcher baseline `work/cloudsave-session-policy-20261113`, `MainActivity.java` Git blob `87583dc20dd67c5faf4ae030e6252eee7f3cd94a`.
- Its `startGoogleDriveAuth(nonce)` wrapper calls `startGoogleDriveAuthWithPolicy(nonce, false)`. The policy method calls `beginGoogleDriveAuth(nonce, selectAccount)`; when true, that method sets `AuthorizationRequest.Prompt.SELECT_ACCOUNT` for the Drive `appData` scope.
- Its nonce-scoped `takePendingStateForNonce` removes only that request's stored result. `clearGoogleAccessToken(token)` calls Google Identity `clearToken()` for the current access token. The inspected baseline has no `cancelGoogleDriveAuth`; PR #19 is the later cancellation extension.
- The inspected historical 0.6.1 native surface exposed `startGoogleDriveAuthWithPolicy`, nonce-scoped `takePendingStateForNonce`, and `clearGoogleAccessToken`, but did not expose native cancellation. This source inspection does **not** establish what the in-progress Remote Play integration exposes at runtime.
- The adapter is selected by the native launcher marker `window.WMLHost`, not by the presence of any one auth method. A launcher object with missing auth methods remains on `android-native` and fails closed; it cannot fall through to browser GIS.
- First connection and explicit logout both require account selection. `startGoogleDriveAuthWithPolicy(nonce, true)` is required to enforce that policy. A legacy one-argument API may be used only for a non-picker restore path; it is rejected for a forced-picker request.
- Explicit logout clears both the runtime token and `hadPreviousAuth`, so native startup restore remains disabled even if persistence of the explicit-logout marker fails. Slot refresh is not run after logout because no valid in-memory token remains.
- Result retrieval is nonce-scoped. Native cancellation is used only when `cancelGoogleDriveAuth` exists; without it, CloudSave ends local polling on cancellation/timeout, but cannot guarantee dismissal of the native account UI.
- `attemptNativeSessionRestore` remains gated by the explicit-logout marker, prior-auth flag, and frozen native adapter. Actual use of this route must be rechecked against the PC launcher's final branch and SHA.

## HTTP / HTTPS direct GIS

- Load GIS during CloudSave setup for the `browser-gis` adapter, before the user clicks.
- The game-button handler calls `initTokenClient` and `requestAccessToken` without awaiting or opening another page first. GIS manages the authorization popup.
- On explicit logout, `prompt: 'select_account'` is passed. Otherwise the remembered-account/first-consent behavior uses `prompt: ''`.
- The callback requires a returned `state` identical to the per-attempt nonce, verifies current auth attempt and session generation, and checks the granted `drive.appdata` scope before applying the token.
- Popup-closed and popup-failed-to-open errors are surfaced in the game UI. Token remains in page memory only.
- Direct GIS requires a compliant JavaScript origin. Google requires HTTPS except localhost/loopback HTTP; the exact game origin also has to be configured in the OAuth Web Client. The known Vercel game origin is `https://wayward-six.vercel.app`, but its Google Console registration could not be inspected.

## file:// constraint and current residual

- `file://` has an opaque `null` origin and cannot run the registered web-origin GIS adapter directly.
- The current PC Host repo offers no OAuth endpoint or secure local callback bridge. Adding one would require a separate authorized Host implementation; it is not invented here.
- The only existing CloudSave-side approach is the isolated HTTPS static bridge and `postMessage` handoff. Its current URL/source availability and number of clicks cannot be confirmed without the corresponding deployed page.
- Therefore file:// is **not complete**: removal of the connection-confirmation page, actual callback return and minimal click count require a compatible one-time bridge to be deployed under an approved Pages/Host endpoint and then tested. A cross-origin page cannot inherit the original game's transient user activation; if that page must start GIS after it loads, another click may be unavoidable unless the bridge can start GIS synchronously inside a trusted user gesture.

## Google GIS policy references

- [GIS Token Model guide](https://developers.google.com/identity/oauth2/web/guides/use-token-model): token flow begins from a user gesture; account selection/sign-in/consent are handled by GIS. A user closing the account/sign-in UI might not invoke the callback.
- [GIS JavaScript API reference](https://developers.google.com/identity/oauth2/web/reference/js-reference): documents `initTokenClient`, `requestAccessToken`, `prompt`, `state`, and `error_callback`.
- [Google OAuth JavaScript-origin rules](https://developers.google.com/identity/protocols/oauth2/javascript-implicit-flow): HTTPS is required except localhost IP/hostname development origins.
- [Google OAuth policies](https://developers.google.com/identity/protocols/oauth2/policies): secure JavaScript origins and redirect URIs are required.
