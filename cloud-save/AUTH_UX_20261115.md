## Android first-login / relogin

- Original failure condition returned `null` when `forceSelectAccount` was true but the host lacked `startGoogleDriveAuthWithPolicy`. `requestGoogleToken` then fell through to the browser bridge.
- Fixed by freezing `AUTH_ADAPTER` once during WML setup and requiring Android calls to use the native adapter when a WMLHost auth surface is present.
- A bridge with a policy overload receives `forceSelectAccount`; a legacy bridge without it uses `startGoogleDriveAuth(nonce)` and remains native. It cannot guarantee forced account selection if the native API lacks that feature.
- Result retrieval always uses the per-nonce pending-result API. Native cancellation is used only when `cancelGoogleDriveAuth` exists; otherwise local polling ends and the native UI itself may remain open.
- `attemptNativeSessionRestore` now accepts either native start API and is gated by the same frozen adapter.

## HTTP / HTTPS direct GIS

- Load GIS during CloudSave setup for the `browser-gis` adapter, before the user clicks.
- The game-button handler calls `initTokenClient` and `requestAccessToken` without awaiting or opening another page first. GIS manages the authorization popup.
- On explicit logout, `prompt: 'select_account'` is passed. Otherwise the remembered-account/first-consent behavior uses `prompt: ''`.
- The callback requires a returned `state` identical to the per-attempt nonce, verifies current auth attempt and session generation, and checks the granted `drive.appdata` scope before applying the token.
- Popup-closed and popup-failed-to-open errors are surfaced in the game UI. Token remains in page memory only.
- Direct GIS requires a compliant JavaScript origin. Google requires HTTPS except localhost/loopback HTTP; the exact game origin also has to be configured in the OAuth Web Client. The known Vercel game origin is `https://wayward-six.vercel.app`, but its Google Console registration could not be inspected.

## file:// constraint and current residual

- `file://` has an opaque `null` origin and cannot run the registered web-origin GIS adapter directly.
- The current PC Host repo offers no OAuth endpoint or secure local callback bridge. Adding one would require a separate authorized Host implementation; it is not invented here.
- The only existing CloudSave-side approach is the isolated HTTPS static bridge and `postMessage` handoff. Its current URL/source availability and number of clicks cannot be confirmed without the corresponding deployed page.
- Therefore file:// is **not complete**: removal of the connection-confirmation page, actual callback return and minimal click count require a compatible one-time bridge to be deployed under an approved Pages/Host endpoint and then tested. A cross-origin page cannot inherit the original game's transient user activation; if that page must start GIS after it loads, another click may be unavoidable unless the bridge can start GIS synchronously inside a trusted user gesture.
