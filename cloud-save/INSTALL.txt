Wayward Google Drive CloudSave — WML v0.6.2

설치
1. cloud-save 폴더를 게임의 wml/mods/ 안에 복사합니다.
2. wml/mods/mods.js의 WML.enable([...])에 "cloud-save"가 있는지 확인합니다. 없을 때만 기존 목록을 보존해 추가합니다.
3. mod.js, crypto.js, README.md, INSTALL.txt가 같은 cloud-save 폴더에 있어야 합니다.
4. 게임을 다시 열고 클라우드세이브 (Google Drive)를 엽니다.

인증
- Android 공식 런처: window.WMLHost가 있으면 네이티브 어댑터로 고정합니다. 인증 API가 없거나 불완전하면 웹 인증으로 우회하지 않고 미지원 오류를 표시합니다. 최초 연결과 로그아웃 후 재로그인은 startGoogleDriveAuthWithPolicy(nonce, true) 및 takePendingStateForNonce가 필요합니다. 정책 API가 없는 구형 startGoogleDriveAuth(nonce) 브리지는 강제 계정 선택 로그인에 사용할 수 없으며, 필요한 경우 비선택 세션 복구에만 사용할 수 있습니다.
- 0.6.1처럼 cancelGoogleDriveAuth가 없는 경우 페이지 측 대기만 nonce별로 중단하며, 실제 네이티브 계정 선택 UI는 취소할 수 없습니다. 최대 180초 대기합니다. 취소 API가 있는 브리지는 요청별 취소와 90초 제한을 사용합니다.
- HTTP/HTTPS: Google Identity Services Token Model을 게임 화면의 연결 버튼 클릭에서 직접 실행합니다. 외부 인증 브리지나 로컬 서버는 사용하지 않습니다. 최초 연결과 명시적 로그아웃 후 재로그인에서 계정 선택을 요청합니다. GIS callback이 누락될 때를 대비해 120초 watchdog으로 재시도 가능하게 복구합니다. HTTPS의 실제 게임 Origin은 Google OAuth Web Client의 Authorized JavaScript origins에 등록되어야 합니다. HTTP 직접 인증은 localhost loopback만 허용하며 LAN IP HTTP는 지원하지 않습니다.
- file://: GitHub Pages 정적 페이지를 팝업으로 엽니다. V4는 event.origin이 'null'(opaque-Origin 분류)이고 event.source가 실제 opener인지 확인합니다. null은 Wayward 정품성 증명이나 file 이외의 다른 opaque context 차단 증명이 아닙니다. 재전송 때 양쪽이 후보 MessagePort를 유지하고, ready를 받은 포트에서 activate를 보내면 페이지가 그 채널만 선택합니다. 모든 메시지는 appId/nonce/requestId/attemptId/sessionId로 묶이며 현재 게임 인증 시도와 세션 generation을 확인합니다. GIS state 및 drive.appdata scope를 검사하고 토큰은 선택된 포트로만 전달합니다. 현재 `https://jeiky224.github.io/cloud/file-auth.html`에 Pages v4 브리지가 배포되어 있으며, 모드의 `FILE_AUTH_BRIDGE_URL`과 일치합니다. 정적 CI 및 handshake 통합 테스트는 통과했지만 실브라우저·실계정·Drive CRUD 검증은 별도 완료가 필요합니다.
- 0.6.1 일회성 accessToken 응답 구조를 유지합니다. 0.7.x 페이지 소유 세션 브리지와 혼합하지 않습니다.
- 인증 nonce는 24바이트 난수의 48자리 16진수입니다.
- Access Token과 Refresh Token은 localStorage, sessionStorage, URL, 게임 세이브에 저장하지 않습니다.
- OAuth 보안 제한: 정적 파일 환경은 GIS Token Model(implicit token)을 사용하며 PKCE code exchange를 구현하지 않습니다. Google은 Token Model의 브라우저 SPA 위험을 경고하고 Code Model + PKCE를 권장하지만, 공식 GIS Code Model 문서는 token 교환을 백엔드 엔드포인트에서 수행하도록 안내합니다. 백엔드를 금지한 현재 조건에서는 Token Model보다 강한 PKCE 보안을 주장할 수 없습니다.
- 사용자에게 보이는 미연결 버튼은 "구글 계정으로 연결"입니다.
- 로그인 유지 설정 버튼은 없습니다. 가능한 범위에서 기존 브라우저 세션/런처 승인을 재사용합니다.

로그아웃
- 현재 메모리 access token과 Android 런처가 가진 해당 access-token 캐시를 삭제합니다.
- 명시적 로그아웃 표식을 남기고 이전 연결 복구 플래그도 제거해 자동 세션 복구를 차단한 뒤 다음 연결에 계정 선택을 요청합니다.
- 최초 연결과 명시적 로그아웃 후에는 브라우저 GIS가 prompt: 'select_account', Android 네이티브 API가 forceSelectAccount=true를 요청합니다. 정책 API가 빠진 Android 런처는 강제 선택을 보장할 수 없으므로 미지원 처리합니다. 계정 선택 정책은 인증 어댑터 선택을 변경하지 않습니다.
- 일반 로그아웃은 Google 앱 권한 철회가 아닙니다. 권한 철회는 별도 버튼으로 수행합니다.
- 로그아웃 표식 저장은 localStorage를 우선하고 실패하면 sessionStorage를 시도합니다. 둘 다 차단되면 페이지 메모리에서만 보존됩니다.

목록 성능
- 저장목록은 Google Drive metadata(files.list)와 opaque Sidecar ID/generation 포인터만 조회합니다.
- 보이는 슬롯만 암호화 Sidecar를 지연 조회하며, Sidecar가 없는 기존 자동 암호화 저장은 보이는 슬롯에서만 backfill을 시도합니다.
- passphrase 암호화 파일은 목록에서 자동 복호화하지 않습니다.
- 실제 저장/불러오기/덮어쓰기에서 선택한 슬롯 본문만 읽습니다.
- 계정별 메타데이터 캐시를 사용하고 목록 조회를 중복 병합합니다.
- 최신 동기화 측정은 브라우저 개발자 콘솔의 [Wayward CloudSave] metadata list metrics에서 확인합니다.

지원 환경
- HTTPS 브라우저: 게임 Origin에서 direct GIS
- HTTP: localhost, 127.0.0.1, [::1] loopback에서만 direct GIS 허용. LAN IP/원격 HTTP는 거부
- file://: GitHub Pages 정적 인증페이지 `https://jeiky224.github.io/cloud/file-auth.html`와 v4 일회성 MessageChannel을 사용합니다. Pages 배포와 자동 handshake 검증은 완료되었으나, 실제 Google 계정/Drive 브라우저 검증 전까지 실사용 완료로 판정하지 않습니다.
- Android: window.WMLHost 런처 식별자가 있으면 native only; 인증 API가 없거나 불완전해도 web fallback 금지. 식별자 자체가 없는 WebView는 런처 측 식별자 제공 여부를 확인해야 합니다.

세이브 호환성
- 기존 Drive appDataFolder, primary 슬롯 ID·파일명·JSON envelope 및 AES-256-GCM 형식을 유지합니다.
- 미리보기 Sidecar도 기존 encryptSnapshotEmbedded 형식으로 별도 암호화합니다. primary appProperties에는 Sidecar ID와 generation 외의 게임 정보가 들어가지 않습니다.
- 메모 버튼은 메모가 있을 때만 나타나고, 팝업은 줄바꿈·긴 글 스크롤·ESC·바깥 터치·Android 뒤로가기를 지원합니다.
- crypto.js는 0.6.1 기준과 변경하지 않습니다.
- 기존 세이브 불러오기 및 삭제 호환성을 유지합니다.
- 이전 passphrase 방식 세이브는 저장 당시 암호화 비밀번호가 필요할 수 있습니다.

중요
이 설치 안내와 자동 테스트는 Google 실제 계정 인증, 권한 승인, Android 기기, 각 브라우저의 팝업 정책 및 실계정 세이브 테스트를 대신하지 않습니다.
